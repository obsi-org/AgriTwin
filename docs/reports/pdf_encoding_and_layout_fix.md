# PDF Encoding and Metadata Layout Fix

## Root Cause

AgriTwin reports use a local dependency-free PHP PDF writer. The generated PDF used the built-in Helvetica font without explicitly declaring WinAnsi encoding, so Western European characters could render or extract incorrectly in some PDF viewers. The Reports page preview also used separate inline metric cards for metadata, which could appear concatenated when copied, extracted or rendered by narrow layouts.

## PDF Mechanism

PDF reports are generated by `agritwin_dashboard/includes/reporting.php` and stored under the ignored runtime directory `var/reports/`. The generator embeds existing logo assets as JPEG image objects and writes text directly into PDF content streams.

## Fix Applied

- The PDF font resource now declares `/Encoding /WinAnsiEncoding`.
- Text continues to be converted from UTF-8 to Windows-1252 before PDF escaping, which supports the Portuguese and Spanish characters used by the platform.
- Report location strings are now localised:
  - English: `Nava de Sotrobal / Macotera, Salamanca, Castile and León, Spain`
  - Portuguese: `Nava de Sotrobal / Macotera, Salamanca, Castela e Leão, Espanha`
  - Spanish: `Nava de Sotrobal / Macotera, Salamanca, Castilla y León, España`
- Report metadata is rendered as a key-value table in the HTML preview with explicit colons and spacing.
- PDF metadata rows include explicit `Label: Value` separators.

## Verification

Verification should generate sample PDFs in `en`, `pt-PT` and `es-ES`, then use `pdftotext` where available to confirm accented text and metadata separators are present. Generated PDFs are runtime artefacts and must not be committed.
